## 1. Data Integrity & Origin Audit

An end-to-end data audit was conducted across both backend and frontend layers to verify the authenticity, origin, and calculation logic of every metric displayed across the 13 reference screens.

### Golden Rules of Texora AI Data Governance
1. **Zero Runtime Fake Services**: All data displayed on runtime screens must originate from database queries executed by the Django REST Framework backend. Fake services are strictly limited to `frontend/test/` automated widget tests.
2. **Transparent Simulation Disclosure**: The application operates on high-fidelity simulated textile factory telemetry. All simulated metrics (such as machine vibration spikes or energy consumption patterns) are transparently labeled as **SIMULATED DATABASE METRICS** or **SIMULATED FACTORY TELEMETRY**.
3. **No Invented or Disconnected Numbers**: Every KPI, chart bar, sparkline, and table row must have an explicit database model origin or a documented deterministic formula.

- **Enhancement**: Add a `@action(detail=False)` on `QualityInspectionViewSet` returning:
  ```json
  {
    "overall_quality_pct": 98.2,
    "total_batches_inspected": 38,
    "defect_rate_pct": 0.8,
  ```

### Absolute Constraints
- **Do not delete test fixtures** in `frontend/test/`.
- **Do not import test fixtures into `frontend/lib/`**.
- **Every runtime service must inherit from or use `http.Client` pointing to `${AppConfig.baseUrl}`**.
- **Label all simulated outputs transparently throughout the UI**.
